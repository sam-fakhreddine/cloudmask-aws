Security Considerations
=======================

Overview
--------

CloudMask is designed to anonymize sensitive AWS infrastructure identifiers. Understanding the security model is crucial for safe usage.

Threat Model
------------

What CloudMask Protects Against
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

✅ **Accidental Exposure**: Prevents leaking AWS resource IDs in shared documents

✅ **LLM Training Data**: Keeps your infrastructure details out of LLM training

✅ **Third-party Analysis**: Share data with external tools safely

✅ **Public Documentation**: Create shareable examples from real infrastructure

What CloudMask Does NOT Protect Against
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

❌ **Determined Attackers**: Hash-based anonymization is reversible with the seed

❌ **Pattern Analysis**: Resource relationships may still be inferrable

❌ **Metadata Leakage**: Timestamps, counts, and structure remain visible

❌ **Brute Force**: Weak seeds can be brute-forced

Security Best Practices
-----------------------

Seed Management
~~~~~~~~~~~~~~~

**DO:**

* Use cryptographically random seeds (32+ characters)
* Generate unique seeds per project
* Store seeds in secure locations (AWS Secrets Manager, HashiCorp Vault)
* Use environment variables for seed injection
* Rotate seeds periodically

**DON'T:**

* Use predictable seeds (dates, names, simple words)
* Reuse seeds across projects
* Commit seeds to version control
* Share seeds with anonymized data
* Use default or empty seeds

Example:

.. code-block:: python

   import secrets
   import os

   # Generate strong seed
   seed = secrets.token_urlsafe(32)

   # Store in environment
   os.environ["CLOUDMASK_SEED"] = seed

   # Use from environment
   from cloudmask import CloudMask
   mask = CloudMask(seed=os.environ["CLOUDMASK_SEED"])

Mapping File Security
~~~~~~~~~~~~~~~~~~~~~

**Critical**: Mapping files contain the reversible mappings!

**DO:**

* Store mapping files separately from anonymized data
* Use encrypted mappings for sensitive data
* Implement strict access controls
* Backup mappings securely
* Delete mappings when no longer needed

**DON'T:**

* Commit mapping files to version control
* Share mapping files publicly
* Store mappings with anonymized data
* Use unencrypted mappings for production data

Example:

.. code-block:: python

   from cloudmask import CloudMask, save_encrypted_mapping

   mask = CloudMask(seed=os.environ["CLOUDMASK_SEED"])
   anonymized = mask.anonymize(text)

   # Save encrypted mapping
   save_encrypted_mapping(
       mask.mapping,
       "mapping.enc",
       password=os.environ["MAPPING_PASSWORD"]
   )

   # Add to .gitignore
   # mapping.enc
   # *.json (mapping files)

Encryption
----------

Mapping Encryption
~~~~~~~~~~~~~~~~~~

CloudMask uses Fernet (AES-128 in CBC mode) for mapping encryption:

.. code-block:: python

   from cloudmask import save_encrypted_mapping, load_encrypted_mapping

   # Encrypt mapping
   save_encrypted_mapping(
       mapping,
       "mapping.enc",
       password="strong-password"
   )

   # Decrypt mapping
   mapping = load_encrypted_mapping(
       "mapping.enc",
       password="strong-password"
   )

Key Derivation
~~~~~~~~~~~~~~

Passwords are derived using PBKDF2-HMAC-SHA256:

* 480,000 iterations (OWASP recommendation)
* Random salt per encryption
* 32-byte derived key

Password Requirements
~~~~~~~~~~~~~~~~~~~~~

**Minimum Requirements:**

* 16+ characters
* Mix of uppercase, lowercase, numbers, symbols
* Not in common password lists
* Unique per mapping file

**Recommended:**

* 32+ characters
* Generated by password manager
* Stored in secrets management system

Access Control
--------------

File Permissions
~~~~~~~~~~~~~~~~

Set restrictive permissions on sensitive files:

.. code-block:: bash

   # Mapping files
   chmod 600 mapping.json
   chmod 600 mapping.enc

   # Configuration files with seeds
   chmod 600 cloudmask.yaml

   # Verify permissions
   ls -la mapping.*

AWS Integration
~~~~~~~~~~~~~~~

Store seeds and passwords in AWS Secrets Manager:

.. code-block:: python

   import boto3
   import json
   from cloudmask import CloudMask

   # Retrieve seed from Secrets Manager
   client = boto3.client('secretsmanager')
   response = client.get_secret_value(SecretId='cloudmask/seed')
   seed = json.loads(response['SecretString'])['seed']

   mask = CloudMask(seed=seed)

Rate Limiting
-------------

Prevent Abuse
~~~~~~~~~~~~~

Use rate limiting for batch operations:

.. code-block:: python

   from cloudmask import CloudMask, BatchRateLimiter

   # Limit to 1000 operations per minute
   limiter = BatchRateLimiter(max_operations=1000, time_window=60)
   mask = CloudMask(seed=seed, rate_limiter=limiter)

   try:
       for text in large_dataset:
           result = mask.anonymize(text)
   except RuntimeError as e:
       print(f"Rate limit exceeded: {e}")

Input Validation
----------------

Prevent Injection
~~~~~~~~~~~~~~~~~

CloudMask validates all inputs:

* Configuration files (YAML schema validation)
* Custom regex patterns (compilation check)
* File paths (path traversal prevention)
* Mapping files (JSON schema validation)

Example:

.. code-block:: python

   from cloudmask import Config

   try:
       config = Config.from_yaml("config.yaml")
   except ValueError as e:
       print(f"Invalid configuration: {e}")

Audit Logging
-------------

Track Usage
~~~~~~~~~~~

Implement audit logging for compliance:

.. code-block:: python

   import logging
   from cloudmask import CloudMask

   logging.basicConfig(
       filename='cloudmask-audit.log',
       level=logging.INFO,
       format='%(asctime)s - %(message)s'
   )

   mask = CloudMask(seed=seed)

   logging.info(f"Anonymization started by {user}")
   result = mask.anonymize(text)
   logging.info(f"Anonymized {len(text)} characters")

   mask.save_mapping("mapping.json")
   logging.info(f"Mapping saved to mapping.json")

Incident Response
-----------------

If Seed is Compromised
~~~~~~~~~~~~~~~~~~~~~~

1. **Immediate Actions:**

   * Rotate seed immediately
   * Re-anonymize all data with new seed
   * Audit access logs
   * Notify stakeholders

2. **Investigation:**

   * Determine scope of exposure
   * Identify affected data
   * Review access patterns
   * Document timeline

3. **Remediation:**

   * Update all systems with new seed
   * Revoke old mappings
   * Implement additional controls
   * Update procedures

If Mapping is Exposed
~~~~~~~~~~~~~~~~~~~~~

1. **Immediate Actions:**

   * Revoke access to exposed mapping
   * Assess data sensitivity
   * Notify affected parties
   * Document incident

2. **Mitigation:**

   * Re-anonymize with new seed
   * Update shared data
   * Implement encryption
   * Review access controls

Compliance
----------

GDPR Considerations
~~~~~~~~~~~~~~~~~~~

CloudMask can help with GDPR compliance:

* **Pseudonymization**: Hash-based anonymization qualifies as pseudonymization
* **Data Minimization**: Share only anonymized data
* **Right to Erasure**: Delete mappings to make data irreversible

**Note**: Consult legal counsel for compliance requirements.

SOC 2 Considerations
~~~~~~~~~~~~~~~~~~~~

For SOC 2 compliance:

* Implement audit logging
* Use encrypted mappings
* Document security procedures
* Regular security reviews
* Access control policies

Reporting Security Issues
-------------------------

If you discover a security vulnerability:

1. **DO NOT** open a public issue
2. Email security@example.com
3. Include detailed description
4. Provide reproduction steps
5. Allow time for fix before disclosure

We follow responsible disclosure practices and will credit reporters.
